## Вопрос 1. Что такое GitHub Copilot и что он умеет?

- **A)** Редактор кода на базе VS Code с чатом по всему проекту
- **B)** AI-ассистент от Microsoft, интегрированный в IDE: автодополнение по контексту, генерация функций по комментариям и предложения по рефакторингу
- **C)** Чат-интерфейс только для проектирования архитектуры
- **D)** Утилита для управления API-ключами Anthropic

<details>
<summary>💡 Показать ответ и объяснение</summary>

**Правильный ответ: B**

По модулю: GitHub Copilot — это AI-ассистент от Microsoft, интегрированный в IDE (Android Studio / IntelliJ IDEA). Умеет:
- автодополнять код на основе контекста;
- генерировать целые функции по комментариям (например, по комментарию `// Функция для валидации email адреса`);

**Почему не другие:**
- A — это описание **Cursor** (AI-first редактор, форк VS Code)
- C — для архитектуры, объяснений и code review модуль рекомендует **Claude / ChatGPT**
- D — API-ключи хранят в `.env`, это не функция Copilot

</details>

- **B)** Задача + Код
- **C)** Только описание задачи — чем короче, тем лучше

## Вопрос 5. Сравни два промпта:

```text
# Плохой
Напиши функцию для валидации формы

# Хороший
Контекст: Я разрабатываю KMP приложение для Android и iOS с Compose UI.
Задача: Создай функцию валидации формы регистрации пользователя.
Ограничения:
- Email должен быть валидным (содержать @ и домен)
- Пароль минимум 8 символов, содержать букву и цифру
- Вернуть Result type с четкой типизацией ошибок
Формат вывода: Kotlin код с KDoc комментариями
```

Чего **не хватает** в плохом промпте?

- **A)** Только примера кода
- **B)** Указания языка Kotlin
- **C)** Контекста, ограничений и формата вывода
- **D)** Ничего — он ничем не хуже

<details>
<summary>💡 Показать ответ и объяснение</summary>

**Правильный ответ: C**

«Плохой» промпт из модуля — это одна строка без контекста, без требований и без заданного формата. AI приходится догадываться обо всём, поэтому результат непредсказуем. Хороший промпт добавляет все три недостающих компонента формулы.

**Почему не другие:**
- A — примеры нужны для few-shot, но здесь главная проблема — отсутствие структуры промпта
- B — язык упомянут в задаче «напиши функцию»; дело не только в нём
- D — неверно: разница принципиальная, это ключевой пример модуля

</details>

## Вопрос 6. Что за техника промптинга здесь использована?

```kotlin
// Пример 1: Валидация email
fun validateEmail(email: String): ValidationResult {
    return if (email.contains("@")) Valid else Invalid("Email должен содержать @")
}

// Пример 2: Валидация пароля
fun validatePassword(password: String): ValidationResult {
    return if (password.length >= 8) Valid else Invalid("Пароль минимум 8 символов")
}

// Теперь создай функцию валидации имени пользователя:
```

- **A)** Few-shot prompting
- **B)** Chain-of-thought prompting
- **C)** Итеративное уточнение
- **D)** Role prompting

<details>
<summary>💡 Показать ответ и объяснение</summary>

**Правильный ответ: A**

Модуль приводит этот фрагмент как пример **few-shot prompting** — когда в промпте даётся несколько примеров, чтобы AI выучил паттерн и продолжил его. В проверке знаний тоже: few-shot = «несколько примеров для обучения паттерну».

**Почему не другие:**
- B — chain-of-thought просит «думать пошагово» и перечислять шаги, а тут даны готовые примеры
- C — итеративное уточнение — это диалог «создай → добавь кэш → добавь retry → напиши тесты»
- D — role prompting задаёт роль эксперта, здесь роли нет

</details>

## Вопрос 7. Как называется приём, когда промпт просит AI рассуждать по шагам?

```text
Задача: Спроектируй архитектуру для кроссплатформенного приложения.

Думай пошагово:
1. Какие слои нужны в Clean Architecture?
2. Что должно быть в commonMain?
3. Какие expect/actual нужны для платформенных особенностей?
4. Как организовать DI с Koin?

Теперь напиши структуру проекта...
```

- **A)** Few-shot prompting
- **B)** Chain-of-thought prompting
- **C)** State hoisting
- **D)** Code review

<details>
<summary>💡 Показать ответ и объяснение</summary>

**Правильный ответ: B**

Фраза «Думай пошагово» (think step by step) — характерный маркер **chain-of-thought prompting**. Модуль использует его и для проектирования архитектуры, и для repository с привычками. AI сначала перечисляет рассуждения, а затем выдаёт решение.

**Почему не другие:**
- A — few-shot опирается на примеры, а не на пошаговые рассуждения
- C — state hoisting из Compose, unrelated к промптам
- D — code review это отдельная задача чата (Claude/ChatGPT), не техника промптинга

</details>

## Вопрос 12. Ты повторяешь промпт, и AI выдаёт почти нужный код. Что делает итеративное уточнение?

```text
Вы: Создай Repository для пользователей
AI: [генерирует код]
Вы: Хорошо, но добавь кэширование в памяти с LRU cache
AI: [обновляет код]
Вы: Теперь добавь обработку ошибок сети с retry policy
AI: [обновляет код]
```

- **A)** Заменяет промпт полностью каждый раз, теряя контекст
- **B)** Отменяет предыдущие изменения AI
- **C)** Автоматически публикует код без проверки
- **D)** Последовательно уточняет результат следующими запросами: кэш → retry → тесты

<details>
<summary>💡 Показать ответ и объяснение</summary>

**Правильный ответ: D**

Диалог из модуля показывает итеративное уточнение: сначала базовый Repository, затем LRU-кэш в памяти, затем retry policy для ошибок сети, и наконец unit-тесты. Каждый следующий промпт уточняет предыдущий результат — это и есть рабочий приём.

**Почему не другие:**
- A — контекст диалога сохраняется, поэтому уточнения работают
- B — наоборот, изменения накапливаются
- C — публикация без проверки противоречит правилам модуля

</details>
