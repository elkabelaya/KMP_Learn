## Вопрос 1. Внимание: ловушка! Какая структура эффективного prompt'а приведена **в этом модуле**?

- **A)** `[Контекст] + [Задача] + [Ограничения] + [Формат вывода]`
- **B)** `[Роль] + [Контекст] + [Задача] + [Ограничения] + [Формат вывода]`
- **C)** `[Задача] + [Готовый код]`
- **D)** `[Роль] + [Примеры]`

<details>
<summary>💡 Показать ответ и объяснение</summary>

**Правильный ответ: B**

Это вопрос-ловушка на внимание. В модуле 1 AI Agent Track формула была «Контекст + Задача + Ограничения + Формат вывода», а **здесь** в начале блока «Основы Prompt Engineering» дана другая формула:

```
[Роль] + [Контекст] + [Задача] + [Ограничения] + [Формат вывода]
```

Роль — полноправный компонент (см. Role prompting ниже). Не переноси формулу из соседнего модуля механически.

**Почему не другие:**
- A — это формула из соседнего модуля, здесь она неполная
- C — слишком упрощённый вариант, в модуле он назван плохим промптом (`Создай KMP проект`)
- D — примеры — это отдельная техника few-shot, а не структура промпта

</details>

## Вопрос 5. Разбери фрагмент «хорошего prompt'а»:

```text
Ты - Senior Kotlin Multiplatform разработчик с 5+ лет опытом.

Контекст:
- Создаю приложение для трекинга эко-привычек (EcoTrack)
- Целевые платформы: Android, iOS, Desktop
- Использую Compose Multiplatform для UI

Задача:
Создай структуру KMP проекта с модулями:
- :app (Android)
- :iosApp (iOS)
- :shared (KMP common code)

Ограничения:
- Kotlin 1.9.20+
- Gradle 8.4+
- Clean Architecture (domain, data, ui слои)

Формат вывода:
1. Дерево структуры проекта
2. build.gradle.kts для каждого модуля
3. Краткое описание назначения каждого модуля
```

Какие **ограничения** здесь заданы?

- **A)** Только Kotlin 1.9.20+
- **B)** Только формат вывода: дерево, build.gradle.kts, описание
- **C)** Kotlin 1.9.20+, Gradle 8.4+ и Clean Architecture (domain, data, ui)
- **D)** Роль Senior разработчика и платформы Android/iOS/Desktop

<details>
<summary>💡 Показать ответ и объяснение</summary>

**Правильный ответ: C**

Секция `Ограничения` содержит ровно три пункта: Kotlin 1.9.20+, Gradle 8.4+, Clean Architecture (domain, data, ui). Это хороший пример конкретных ограничений — в отличие от плохого промпта `Создай KMP проект`.

**Почему не другие:**
- A — неполный список
- B — это «Формат вывода», отдельный компонент формулы
- D — это «Роль» и «Контекст», тоже другие компоненты

</details>

## Вопрос 6. Какая техника используется в этом фрагменте?

```text
Создай expect/actual для работы с файловой системой.

Пример 1 - SharedPreferences:
expect interface Preferences {
    fun getString(key: String): String?
}
actual class Preferences actual constructor(...) { ... }

Пример 2 - UserDefaults:
expect interface Storage {
    fun save(data: String, key: String)
    fun load(key: String): String?
}

Теперь создай для FileIO с методами read() и write().
```

- **A)** Few-shot prompting
- **B)** Chain of Thought
- **C)** Role prompting
- **D)** Итеративное уточнение

<details>
<summary>💡 Показать ответ и объяснение</summary>

**Правильный ответ: A**

Два законченных примера (SharedPreferences и UserDefaults) задают паттерн, и AI должен применить его к новой задаче FileIO — это классический **few-shot prompting** из модуля.

**Почему не другие:**
- B — chain of Thought просит пошаговые рассуждения, а здесь готовые образцы кода
- C — роли эксперта в промпте нет
- D — это один запрос, а не серия уточнений

</details>

## Вопрос 7. В примере Chain of Thought для repository с привычками как предлагается обрабатывать ошибки?

```text
Создай repository для работы с привычками.

Подумай пошагово:
1. Какие данные нужно хранить? (id, title, category, streak)
2. Какие операции нужны? (CRUD + поиск по категории)
3. Как кэшировать данные? (in-memory cache с TTL)
4. Как обрабатывать ошибки? (sealed class Result)

Теперь напиши код.
```

- **A)** Через `try/catch` в каждом методе
- **B)** Через sealed class Result
- **C)** Через возврат `null`
- **D)** Ошибки в примере не упоминаются

<details>
<summary>💡 Показать ответ и объяснение</summary>

**Правильный ответ: B**

Пункт 4 промпта прямо гласит: «Как обрабатывать ошибки? (sealed class Result)». Заодно пример задаёт типичный для KMP набор: id/title/category/streak, CRUD + поиск по категории и in-memory cache с TTL.

**Почему не другие:**
- A — в промпте указан конкретный механизм, а не общий try/catch
- C — `null` не описан
- D — ошибки описаны в пункте 4

</details>

## Вопрос 9. Что делает строка `tabAutocompleteModel` в этом конфиге?

```javascript
// .continue/config/continue.config.js
module.exports = {
  models: [
    {
      title: "Claude 3.5 Sonnet",
      apiBase: "https://api.anthropic.com",
      apiKey: process.env.ANTHROPIC_API_KEY,
    },
  ],
  tabAutocompleteModel: "Claude 3.5 Sonnet",
};
```

- **A)** Устанавливает модель для автодополнения по Tab в Continue.dev
- **B)** Сохраняет API-ключ в исходном коде
- **C)** Запускает локальную модель через Ollama
- **D)** Устанавливает плагин GitHub Copilot

<details>
<summary>💡 Показать ответ и объяснение</summary>

**Правильный ответ: A**

`tabAutocompleteModel` указывает Continue.dev, какую из объявленных моделей использовать для inline-автодополнения (Tab). Ключ при этом берётся из переменной окружения `process.env.ANTHROPIC_API_KEY` — в файле нет секрета в открытом виде.

**Почему не другие:**
- B — как раз наоборот: ключ читается из env, а не хардкодится
- C — Ollama упоминается как возможность Continue.dev, но в этом конфиге API base — `api.anthropic.com`
- D — Copilot настраивается отдельно через расширение VS Code

</details>

## Вопрос 10. В Step 3 проекта «Hello KMP» нужно добавить кнопку, меняющую текст. Что предписывает промпт?

```text
Добавь в Greeting.kt кнопку, которая меняет текст при нажатии.

Используй:
- StateHoisting с remember { mutableStateOf(...) }
- Material3 Button компонент
- ClickListener

Покажи полный обновленный код Greeting.kt.
```

- **A)** `TextView` из Android XML
- **B)** Глобальную переменную без remember
- **C)** `var text by remember { mutableStateOf("Hello") }`, `Button(onClick = { ... })` из Material3
- **D)** `SharedPreferences` для хранения текста

<details>
<summary>💡 Показать ответ и объяснение</summary>

**Правильный ответ: C**

- A — доверие на 100% названо ошибкой
